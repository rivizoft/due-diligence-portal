# PDF watermark при просмотре и скачивании

Статус: спецификация для пользовательского ревью. Реализация не начата.

## Цель и согласованное поведение

Настройки watermark должны реально применяться ко всем страницам PDF при просмотре и скачивании текущей и исторических версий. Оригинальные байты в хранилище не меняются. Подготовка начинается по запросу пользователя, после авторизации и проверки доступа. Готовый результат повторно используется из кеша.

Пользователь согласовал открытие PDF в новой вкладке. Эта вкладка сразу показывает спиннер и сообщение о подготовке. После подготовки и загрузки файла появляется стандартный просмотрщик браузера. При скачивании спиннер появляется в нажатой кнопке до получения файла; повторное нажатие блокируется. Ошибка завершает ожидание и позволяет повторить запрос.

## Текущее состояние

- Backend: Go, Echo, SQLite. `Download` и `DownloadVersion` в `internal/handler/document_handler.go` возвращают `version.FileData` без обработки.
- Настройки хранятся в `WatermarkRepository`: enabled, text_template, position, opacity, font_size, color.
- Шаблоны: user_email, user_name, date, document_name. Имя и email доступны в JWT middleware.
- Frontend: Svelte; JWT хранится в localStorage и отправляется заголовком Authorization. Скачивание уже использует fetch и Blob.
- Отдельного просмотра PDF нет. Версии PDF хранятся в SQLite как байты и загружаются целиком. Лимит загрузки по умолчанию — 100 MiB, конфигурируемый до 2 GiB. Ограничение числа преобразований само по себе не гарантирует ограничение всей памяти приложения.

## Выбранный подход

Общий сервис подготовки PDF вызывается из обработчиков просмотра и скачивания. Запрос ожидает результат; отдельных фоновых заданий, polling и внешней очереди в первой версии нет. Обработчик отдаёт готовый PDF только после успешной обработки. Варианты «каждый раз без кеша» и «при загрузке» отклонены из-за повторной нагрузки и невозможности удобной персонализации соответственно.

Использовать PDF-библиотеку для наложения текстового watermark без растеризации страниц, сохраняя поиск и выделение текста. На этапе плана проверить пригодность pdfcpu, поддержку Unicode с встраиваемым шрифтом, лицензии библиотеки и шрифта и поведение на повёрнутых страницах. Не менять библиотеку в процессе реализации без проверки этих требований.

Watermark поддерживает все существующие позиции, непрозрачность, размер и цвет. `date` — календарная дата UTC в формате YYYY-MM-DD; она фиксируется один раз на запрос. Подстановка переменных буквальная, все вхождения заменяются. Неподдерживаемые переменные отклоняются при сохранении конфигурации. Текст должен оставаться читаемым на страницах разных размеров и ориентаций; нужен тест длинного текста и кириллицы.

При выключенном watermark PDF отдаётся без преобразования. Другие типы файлов продолжают скачиваться без изменений. При включённом watermark повреждённый, зашифрованный или неподдерживаемый PDF возвращает понятную ошибку без выдачи оригинала. Изменение подписанного PDF может нарушить цифровую подпись; это предупреждение показывается в настройках watermark.

## API и права доступа

Существующие download endpoints сохраняют адреса и attachment-поведение. Добавляются GET `/documents/:id/preview` и GET `/documents/:id/versions/:version/preview`, возвращающие PDF inline. Preview применяется только к PDF.

Проверка JWT, существующих ограничений доступа и доступности документа выполняется до чтения кеша. Перед выдачей после длительной подготовки повторно проверяется доступ. Используется существующий `canAccessDocument`.

Правило доступа после уточнения пользователя: endpoints, возвращающие PDF, требуют `AccessDownload`. Пользователям только с `AccessView` сервер возвращает метаданные и изображения отдельных страниц, но никогда PDF, включая fallback. Режим определяется действующими серверными правами. Скрытие кнопок стандартного просмотрщика или PDF.js недостаточно, если PDF передаётся в браузер. Изображения и скриншоты сохранять технически возможно; гарантируем запрет получения PDF-файла через API для права только просмотра.

Персональные ответы получают `Cache-Control: private, no-store`. JWT не передаётся в URL. Ошибки используют существующий JSON envelope. Обработчики регистрируют успешную выдачу в аудите после подготовки; запросы, которые не смогли подготовить PDF, не помечаются успешным скачиванием. Сервер не может подтвердить фактическое сохранение файла пользователем.

## Кеш и нагрузка

Кеш приватных готовых PDF хранится во временном каталоге сервера вне статической раздачи, с ограниченными правами. Запись атомарная, частичные результаты не выдаются. Перезапуск может очистить кеш: это не постоянное хранилище.

Ключ — SHA-256 от идентификатора документа и версии, хеша исходных байтов, ID пользователя, всех полей конфигурации, итогового текста и версии рендерера. Хеш полей важнее updated_at: текущая точность updated_at — секунды. Имя документа и дата учитываются через итоговый текст. Изменение настроек или версии делает старый результат недоступным новым запросам; старые записи удаляются по TTL или лимиту размера. Запрос, уже начавший обработку, использует свой снимок настроек.

Начальные конфигурируемые значения: две одновременные генерации на процесс, до восьми ожидающих разных генераций, TTL 15 минут, кеш до 512 MiB, ожидание подготовки до 60 секунд, максимум исходного PDF для преобразования 100 MiB. Превышение размера возвращает явную ошибку; оригинал при включённом watermark не выдаётся. Лимит watermark независим от общего лимита загрузки и объясняется в документации администратора.

Одинаковый ключ объединяет параллельные запросы в одну генерацию. Завершение одного клиента не отменяет работу для остальных; при отсутствии ожидающих отменяется, если выбранный движок поддерживает отмену. Переполнение очереди возвращает 503 с Retry-After, превышение времени — ошибку с возможностью повтора. Если библиотека не поддерживает прерывание, слот занят до фактического завершения; таймаут HTTP не считается остановкой преобразования.

Лимит допуска проверяется до чтения тяжёлых данных там, где позволяет repository API. При необходимости добавить чтение метаданных версии отдельно от FileData. Размер кеша ограничивается по сумме файлов с вытеснением наименее недавно использованных записей. Результат больше лимита кеша отдаётся без кеширования, временный файл удаляется после выдачи.

При нескольких экземплярах сервера каждый имеет собственный кеш и ограничения. Общий кеш и распределённая очередь за пределами первой версии.

## Просмотр без права скачивания

Этот раздел уточняет и заменяет общий поток стандартного просмотра ниже для пользователей без AccessDownload. При выключенном watermark изображения страниц всё равно генерируются, без watermark; исходный PDF не выдаётся.

Добавляются авторизованные endpoints метаданных (число страниц и размеры) и изображений отдельных страниц текущей и исторической версии. Они требуют AccessView. На каждый запрос проверяются действующие права и доступность документа, включая кеш; после длительной подготовки проверка повторяется.

Сервер растеризует страницы PDF с уже нанесённым watermark. Он становится частью изображения, а не отдельным слоем интерфейса. На этапе плана проверить MuPDF или Poppler: лицензия, поддержка деплоя, изоляция процесса, ограничения ресурсов и таймауты. Вызов без shell, с доверенными аргументами. Ошибка обработки никогда не приводит к выдаче PDF.

Новая вкладка показывает нашу страницу с вертикальным списком изображений и навигацией по страницам, без кнопок скачивания и печати. Спиннер подготовки виден до первой страницы. Следующие страницы загружаются по мере прокрутки, с предзагрузкой одной соседней страницы; имеют свой индикатор и повтор после ошибки. Поиск и выделение текста в этом режиме в первую версию не входят.

Начальные ограничения изображений: PNG, максимум 1600 пикселей по длинной стороне и 4 миллиона пикселей на страницу; произвольный DPI от клиента не принимается. Полная растеризация документа заранее не выполняется. PDF и изображения используют общий кеш 512 MiB. Ключ изображения дополнительно содержит страницу, разрешение, формат и версию raster renderer. Одинаковые запросы страницы объединяются.

Общий лимит двух тяжёлых операций распространяется на подготовку PDF и растеризацию. Вложенный захват слотов запрещён: сначала завершается подготовка PDF, затем отдельным этапом генерируется страница. Таймаут raster subprocess должен фактически останавливать процесс. Изображения повышают нагрузку; измерять отдельно время появления первой страницы, листания, пиковую память и объём кеша.

Все запросы изображений используют JWT через общий binary helper с refresh, без токена в URL. Blob URL изображений освобождаются при удалении из интерфейса и уходе. Кнопки скачивания отображаются по правам; backend независимо запрещает выдачу PDF без AccessDownload. Стандартный просмотрщик и fallback скачивания ниже применяются исключительно к пользователям с AccessDownload.

## Пользовательский интерфейс

Кнопка Open PDF добавляется в список, карточку и строки PDF-версий. Она открывает same-origin страницу подготовки обычной ссылкой target=_blank с rel=noopener. Токен не передаётся через opener.

Страница подготовки получает PDF авторизованным fetch через общий binary helper API-клиента с существующим однократным refresh JWT, создаёт Blob URL и встраивает просмотрщик в ту же вкладку. Страница сохраняется как оболочка, чтобы освободить Blob URL при уходе. При отсутствии поддержки встроенного просмотра предлагается скачать уже полученную копию. AbortController отменяет запрос при уходе со страницы; Blob URL освобождается при замене файла и закрытии страницы.

Спиннер покрывает серверную подготовку и загрузку PDF в браузер. Процент готовности не показывается: достоверного прогресса рендерера нет. При попадании в кеш ожидание остаётся только на передачу файла. Fetch+Blob требует получить файл целиком до появления просмотра; потоковый просмотр и Range-запросы в первой версии не поддерживаются.

Кнопки скачивания списка, карточки и старых версий показывают состояние ожидания отдельно для выбранного файла и понятную ошибку. Доступность элементов: статус aria-live, текстовая подпись спиннера, доступная кнопка повтора. Язык надписей соответствует текущему английскому интерфейсу.

Настройки получают пояснение, что функция применяется к PDF при просмотре и скачивании. Превью на образце страницы отображает выбранное расположение и все четыре переменные; оно демонстрационное, не обещает точное совпадение браузерных и PDF-шрифтов.

## Проверка и критерии приёмки

- Реальные PDF-ф fixtures: несколько страниц, разные размеры, rotation, Unicode, длинный текст. Проверить все позиции, цвет, opacity и font size; сохранить исходные байты и извлекаемый текст.
- Handler tests: enabled/disabled, не-PDF, текущая/историческая версия, ошибки конфигурации и обработки, отсутствие авторизации и доступа, отзыв доступа во время ожидания, кеш без обхода проверок.
- Режим AccessView: PDF отсутствует в сетевых ответах, все PDF endpoints запрещены, watermark встроен в изображения, страницы загружаются лениво, границы страницы и разрешения проверяются, отзыв доступа между страницами блокирует выдачу, ошибка рендеринга не включает PDF fallback. Ручная проверка обоих режимов и исторических версий.
- Cache tests с контролируемым renderer: персональные ключи, смена настроек в одну секунду, дата, версия, singleflight, TTL, вытеснение, очередь, отмена, отсутствие частичных файлов.
- Frontend: новая вкладка со статусом до ответа, успешный просмотр, повтор после ошибки, refresh токена, состояние кнопок скачивания, освобождение Blob URL.
- Замеры на небольшом PDF и PDF около лимита: холодная и повторная выдача, параллельные разные пользователи, объединение одинаковых запросов, пиковые RSS и размер временных файлов. Числовой SLA не заявляется до замеров. Результаты определить как основание для настройки лимитов.
- Выполнить релевантные Go-тесты, race-проверку сервиса кеша, frontend typecheck/build и ручной просмотр PDF в доступном браузере.

## Границы

Не меняем оригиналы, не генерируем копии при загрузке, не добавляем watermark к загруженным изображениям/Office-файлам. Для AccessView строим простой просмотр серверных изображений страниц. Для AccessDownload используем стандартный просмотрщик. Не обещаем защиту от сохранения изображений, скриншотов или восстановления документа из изображений. Для подписанных документов и документов сверх лимита действуют явно описанные ограничения.
